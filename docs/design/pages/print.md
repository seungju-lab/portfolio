# 전체 열람과 PDF

`/print/`는 소개와 세 프로젝트를 한 번에 읽고, 같은 디자인과 내용을 PDF로 저장하는 문서다. [변경 요구사항](../full-read-pdf-change-requirements.md)을 따른다. 웹과 PDF는 남색·청록색, 로컬 글꼴, 사진, 아키텍처 도식과 본문을 공유한다. 별도 요약본이나 4장짜리 흑백 문서를 만들지 않는다.

## 내용과 읽는 순서

1. 홈으로·PDF로 저장 도구 모음.
2. 기존 프로필 사진, 이승주·Backend Developer, 소개 문단.
3. ILOG·Lorekeeper·Matching SSAFY의 역할 요약과 해당 프로젝트로 이동하는 목차.
4. 교육·활동, 홈서버·이슈 관리 설계 경험, 확인된 GitHub 연락 경로.
5. 세 프로젝트 전체 본문. 각 프로젝트 안에서 프로젝트 개요 → 아키텍처 → 문제 해결 → 결과 순으로 읽는다.

2026-09-15에 [8장 압축안](../pdf-compact-comparison.md)을 채택했다. 소개·목차·교육을 첫 장에 묶으며, 웹도 같은 문서 순서를 따른다. 웹의 본문은 한 열로 유지하고 두 열 배치와 페이지 나눔은 인쇄에서 적용한다.

소개·교육·활동은 [홈 콘텐츠](../../../src/content/portfolio.ts), 프로젝트 본문·담당 범위·검증 한계는 [상세 콘텐츠](../../../src/content/project-details.ts)가 기준이다. 도식·사례·결과·회고를 포함해 상세 본문을 제공하며 인쇄 때문에 축약하지 않는다. 새 이메일이나 성과 수치를 만들지 않는다.

프로젝트 제목·기간·역할·소개·기술 태그·저장소 링크를 먼저 배치하고 네 섹션은 [상세 명세](project-detail.md)를 재사용한다. 전체 열람에서는 프로젝트 제목을 h2, 네 섹션을 h3, 내부 제목을 h4로 내려 문서 전체 제목 계층을 유지한다. 앵커는 프로젝트 slug를 접두사로 사용해 충돌을 피한다.

## 웹의 배치와 표현

중앙 본문은 최대 760px, 데스크톱 위아래 여백은 80px이다. 모바일 좌우 여백은 24px, 상단은 48px로 한다. 사진은 홈의 같은 자산을 사용하며 소개 오른쪽에 96×120px, 360px 미만에서 80×100px로 배치한다. 소개 문단은 아래에서 본문 폭을 사용한다.

목차는 프로젝트 이름·번호를 강조하고 기간·담당 역할을 보조 정보로 둔 세 개의 행이다. 큰 프로젝트 제목과 구분선, 프로젝트 사이 80px(모바일 64px) 여백으로 경계를 드러낸다. 프로젝트 제목 40px(모바일 32px), 네 섹션 24px(모바일 22px), 본문 16px·행간 1.8을 시작값으로 사용한다. 도식과 결과 묶음의 선·태그·색은 기존 상세 디자인을 따른다.

커서 조명, 다른 행 흐림, 고정 소제목은 사용하지 않는다. 링크·버튼의 hover와 키보드 focus는 [공통 컴포넌트](../components.md#textlink와-비조작-요소)를 따른다. 목차는 실제 앵커 링크로 마우스·Enter·터치에서 해당 프로젝트로 이동한다. 직접 hash 진입과 뒤로 가기를 지원하며 기본 스크롤과 움직임 줄이기 설정을 존중한다.

## A4 배치

[공통 인쇄 규칙](../foundations.md#인쇄)을 적용한다. 웹의 색·사진·도식·본문을 유지하면서 A4 폭·여백과 페이지 나눔을 조정한다. 본문 14px(10.5pt)·행간 1.7, 프로젝트 제목 28px, 네 섹션 21px, 내부 제목 16px, 도식 글자 12~14px를 초기값으로 둔다. 실제 출력에서 읽기 어렵다면 내용을 줄이거나 글자를 더 작게 만들지 말고 페이지를 늘린다.

소개·목차·교육·연락을 첫 장에 묶고 각 프로젝트를 새 페이지에서 시작한다. 목차는 이름과 기간·역할을 한 행에, 교육 이력은 두 열에 배치한다. 프로젝트 제목 옆에는 기간을 두고 저장소와 상세 링크는 한 행으로 묶는다. 개요의 주요 기능·담당 범위는 두 열에 배치한다. 개요 다음의 아키텍처를 같은 장에 두며, 도식의 연결 레이블·화살표를 가로로 묶어 세로 간격을 줄인다. ILOG의 브라우저→Gateway 진입도 가로로 배치한다. 요청 방향과 담당 표시는 유지한다.

문제 해결은 새 페이지에서 시작한다. ILOG는 첫 두 사례를 한 장에, 마지막 사례와 결과·회고를 다음 장에 둔다. Lorekeeper와 Matching SSAFY는 각 프로젝트의 두 사례와 결과를 한 장에 묶는다. 이어지는 페이지 상단에는 프로젝트 이름을 표시한다. 제목과 다음 내용, 개별 사례·도식·결과 묶음을 함께 유지한다. 빈 페이지, 잘린 도식, 제목만 남은 페이지와 과도한 빈 공간은 조정 대상이다. 내용이 늘어나면 페이지도 늘릴 수 있으며, 높이를 고정하거나 넘치는 본문을 숨기지 않는다.

Pencil의 기존 12장과 비교한 8장안을 구현 기준으로 사용한다. A4 시안은 794×1123px이며 [압축안 문서](../pdf-compact-comparison.md)에 프레임 ID와 전체 본문 대조 결과가 있다. 2026-09-15 Chromium 실제 출력은 소개·목차·교육 1장, ILOG 3장, Lorekeeper 2장, Matching SSAFY 2장인 총 8장이다. [코드·PDF 검증 기록](../../verification/compact-pdf.md)에 최종 PDF와 검증 범위를 남긴다. 브라우저와 인쇄 설정에 따라 페이지 수가 달라질 수 있다. 시안의 링크 표현만으로 실제 PDF 작동을 검증했다고 판단하지 않는다.

## PDF 링크

저장소, 프로젝트 상세 웹 주소와 GitHub 연락 경로는 클릭 가능한 외부 링크로 유지한다. 각 프로젝트 제목 근처에 상세 페이지 링크를 둔다. PDF에서는 시안처럼 짧은 링크 레이블을 표시하고 실제 주소는 링크 목적지로 보존한다. GitHub 연락 링크는 주소 자체를 레이블로 사용한다. 주소를 본문 아래에 중복 출력하지 않는다.

목차는 같은 PDF 안의 프로젝트 시작 위치로 이동한다. 본문과 링크를 보존하는 브라우저 출력을 사용하며 전체 페이지를 이미지로 바꾸지 않는다. PDF 저장 버튼·오류 안내 등 출력 후 쓸모없는 조작 요소만 숨긴다. 목차나 외부 링크를 버튼과 함께 일괄 숨기지 않는다.

## 도구 모음과 인쇄 반응

도구 모음은 문서 흐름 안에 둔다. 인쇄 버튼은 기본 제목색, hover·focus에서 청록색이며 색에만 공통 전환을 쓴다. 버튼 옆에는 브라우저 인쇄에서 PDF로 저장할 수 있다는 안내와 남색 배경이 보이지 않을 때 배경 그래픽을 켜라는 안내를 제공한다. 실제 브라우저에서 필요한 설정을 확인하고 안내를 조정한다.

| 상황                   | 동작·결과                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 홈으로                 | 같은 탭의 `/`로 이동한다. 뒤로 가기로 재진입하면 이전 열람 위치를 복원한다.                                                                |
| PDF로 저장             | 실제 button의 클릭·Enter·Space·터치로 브라우저 인쇄 대화상자를 연다. 저장 위치와 인쇄 대상은 브라우저에서 선택한다.                        |
| 대화상자 열림          | 인쇄 종료까지 중복 실행을 막는다. 다운로드 진행률이나 저장 성공을 임의로 표시하지 않는다.                                                  |
| 저장·인쇄·취소 후 복귀 | 기존 스크롤 위치를 유지하고 버튼으로 시작했다면 버튼에 포커스를 복원한다. 파일 저장 성공을 추정하지 않으며 재실행할 수 있어야 한다.        |
| 브라우저 메뉴·단축키   | 버튼과 같은 내용·스타일을 출력한다. 종료 후 기존 포커스를 유지하며 버튼으로 강제 이동하지 않는다.                                          |
| 호출 불가·실패         | `인쇄 창을 열지 못했습니다. 브라우저 메뉴의 인쇄 기능을 이용해 주세요.`를 표시하고 보조 기술에도 알린다. 본문·홈 이동과 재시도를 유지한다. |

인쇄가 닫히면 화면 배치를 복원한다. 이미 페이지를 떠났으면 이전 인쇄 종료 처리로 포커스를 옮기지 않는다.

## 검토 기준

웹은 1440/390px 시안, 320px·전환 너비·200% 텍스트 확대에서 본문·사진·도식·링크의 잘림과 가로 넘침을 확인한다. 모든 프로젝트 본문을 상세 콘텐츠와 대조하고 목차 직접 진입·키보드·터치·뒤로 가기를 확인한다.

실제 PDF의 모든 페이지를 렌더해 색·사진·도식·전체 내용과 페이지 나눔을 확인한다. 한글 글꼴 포함, 텍스트 선택·검색, 외부 링크의 실제 목적지와 내부 목차 이동을 검사한다. 대표 PDF 뷰어에서 링크를 실제 실행한다. 배경 그래픽 설정에 따른 결과, 브라우저·뷰어 버전, 페이지 수와 재현 방법을 기록한다. 자동 출력 검증과 실제 대화상자·실제 모바일에서 확인한 범위를 구별한다.

버튼과 메뉴 각각으로 인쇄를 열고 취소 후 재실행한다. 저장 버튼과 focus 외곽선은 출력되지 않으며 배경·본문·링크는 남아야 한다. 오류 조건, 스크롤·포커스 복원, 홈·상세 회귀와 정적 빌드를 확인한다. 이전의 고정 4장·문단 수 검사는 새 전체 콘텐츠와 출력 품질 기준으로 바꾼다.
