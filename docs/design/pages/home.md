## 커서 조명

홈과 프로젝트 상세에만 적용한다. [공통 포인터 조건](../foundations.md#반응과-움직임)을 만족하는 화면에서 첫 포인터 이동이 발생하면 표시한다. 배경 위·본문 아래의 고정 레이어에 `radial-gradient(600px at x y, rgba(29,78,216,.15), transparent 80%)`를 그린다. 레이어는 포인터 이벤트와 접근성 트리에서 제외해 링크·텍스트 선택을 방해하지 않는다.

중심은 화면 기준 `clientX/clientY`이며 프레임마다 마지막 좌표를 한 번 반영한다. 좌표 자체에는 지연·보간을 추가하지 않는다. 문서만 스크롤하면 중심은 같은 화면 위치에 남는다. 진입 시 opacity 0→1, 화면 이탈·창 비활성 시 1→0에 공통 전환을 사용한다. 재진입하면 최신 좌표로 다시 표시한다. 화면 크기·입력 조건 변경이나 움직임 줄이기 활성화 시에는 즉시 숨기고 추적을 중단한다. 조명이 꺼져도 콘텐츠와 조작 상태는 동일하게 읽혀야 한다.

## 목차와 스크롤

소개 `#about`, 프로젝트 `#projects`, 교육·활동 `#education`을 실제 문서 앵커로 제공한다. 데스크톱 왼쪽 고정 조건은 [공통 구성](../foundations.md#구성)을 따른다. 모바일에서는 소개와 가로 목차도 함께 스크롤되고 각 본문 섹션의 짧은 소제목만 해당 섹션 안에서 `top: 0`에 붙는다. 소제목 영역은 높이 60px, 배경 `rgba(15,23,42,.95)`, 가로 여백 24px다. 본문보다 위에 두며 다음 섹션에 진입하면 이전 소제목이 밀려난다. 별도의 배경 blur는 사용하지 않는다.

| 상황                | 동작·완료 조건                                                                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 최초 진입           | hash가 없으면 소개를 선택한다. 유효한 hash로 직접 들어오면 해당 섹션으로 이동한다. 없는 hash는 오류 화면 없이 기본 본문을 유지한다.                                                                 |
| 목차 실행           | 클릭·Enter·터치로 hash를 변경하고 해당 소제목 위 여백이 데스크톱 96px, 모바일 80px가 되도록 스크롤한다. 이동 시간은 공통 규칙을 따른다. 동일 항목 재실행은 history를 중복 추가하지 않는다.          |
| 활성 판정           | 화면 상단에서 데스크톱 128px·모바일 80px 지점을 지난 마지막 섹션을 선택한다. 소제목의 sticky 위치 대신 섹션 시작 위치로 판정한다. 처음 섹션 이전에는 소개, 문서 맨 아래에서는 교육·활동을 선택한다. |
| 이동 중·수동 스크롤 | 현재 보이는 섹션을 따라 선택을 갱신한다. 수동 스크롤은 hash와 포커스를 바꾸지 않는다. 휠·터치 스크롤·스크롤 키로 개입하면 진행 중인 앵커 이동을 중단하고 이전 목적지로 복귀하지 않는다.             |
| 빠른 재실행         | 다른 목차를 실행하면 최신 목적지만 유효하다. 취소된 이동의 완료 처리로 목차·포커스가 되돌아가지 않는다.                                                                                             |
| 도착·포커스         | 명시적인 목차 이동이 완료되면 대상 제목에 프로그램 방식으로 포커스를 옮기되 추가 스크롤은 막는다. 제목은 일반 Tab 순서에 넣지 않는다. 다음 Tab은 도착한 섹션의 첫 링크로 이어진다.                  |
| 뒤로·앞으로         | 브라우저의 hash·스크롤 복원을 따른다. 복원 후 실제 위치로 선택을 다시 판정하고 매번 페이지 맨 위로 초기화하지 않는다.                                                                               |

위 활성 판정선과 포커스·중단 규칙은 포트폴리오의 자체 설계다. JavaScript가 실행되기 전에도 앵커 이동과 상세 링크는 작동해야 한다. 스크롤에 따른 목차 갱신은 스크립트로 보완한다.

## 반응 검토 기준

- 1440×1000에서 포인터 이동·문서 스크롤·창 이탈·재진입을 실행한다. 조명 중심이 화면 좌표를 따르고 링크 클릭과 텍스트 선택이 가능해야 한다.
- 프로젝트 목차 실행 후 휠로 중단하고 다른 목차를 누른다. 취소된 목적지로 튀지 않고 최신 요청이 완료되어야 한다. 이어 수동 스크롤하면 hash는 유지되면서 선택 표시만 바뀌어야 한다.
- 각 hash로 직접 진입하고 목차 이동 뒤 브라우저 뒤로·앞으로를 실행한다. 소제목이 가려지지 않고 선택 표시가 위치와 일치해야 한다. 키보드 이동 완료 뒤 Tab이 해당 섹션의 링크로 이어져야 한다.
- 390/320px에서 터치 스크롤과 목차 탭을 실행한다. 가로 목차가 잘리지 않고 고정 소제목은 하나씩 교체되며 조명·다른 행 흐림이 없어야 한다. 낮은 데스크톱 창에서는 왼쪽 하단 링크까지 스크롤로 접근할 수 있어야 한다.
- 움직임 줄이기를 실행 중 켰다 끈다. 켜면 즉시 움직임이 멈추고 모든 탐색은 계속 가능해야 한다. 끈 후 다음 포인터 입력부터 효과가 다시 적용되어야 한다.

## 시각 검토 기준

1440px에서 이름·직무와 첫 프로젝트가 초기 1000px 안에 보여야 한다. 390/320px에서 이름, 소개, 목차, 본문 순서가 유지되고 가로 잘림이 없어야 한다. 소개와 목록의 시작점을 넓은 여백으로 구분하되 오른쪽 본문이 빈 화면처럼 보이지 않게 한다. 프로젝트 날짜·역할·본문은 서로 다른 위계로 읽혀야 한다. 카드 테두리·번호·도해를 반복해서 레퍼런스의 간결한 구성을 바꾸면 재검토한다.
