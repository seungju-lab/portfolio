# PDF 제공

홈의 `PDF 보기`로 생성된 정적 파일을 열고 PDF 뷰어에서 저장한다. 웹으로 읽을 때는 `전체 열람`을 사용한다.

## 홈 링크와 동작

홈 목차 아래에 다음 세 줄을 배치한다. 각 줄에 하나의 링크를 둔다.

```text
GitHub
전체 열람
PDF 보기
```

| 링크      | 목적지                      | 실행 결과                                                |
| --------- | --------------------------- | -------------------------------------------------------- |
| GitHub    | `https://github.com/ju1115` | 새 탭으로 이동한다.                                      |
| 전체 열람 | `/print/`                   | 같은 탭에서 웹 전체 문서를 읽는다.                       |
| PDF 보기  | `/portfolio.pdf`            | 새 탭에서 PDF를 연다. 브라우저의 PDF 처리 설정을 따른다. |

보기 링크의 접근 가능한 이름에는 `새 탭`을 포함한다. 파일 저장은 PDF 뷰어의 다운로드 기능을 사용한다. 브라우저의 PDF 처리 설정을 따르며 자체 뷰어·진행률·성공 알림을 만들지 않는다.

## 배치와 상태

공통 TextLink의 색·서체·아이콘·hover·focus를 재사용한다. GitHub 로고, 전체 열람의 문서 아이콘, PDF 보기의 새 탭 화살표로 동작을 구분한다. 아이콘은 보조 표시이며 각 링크에 전체 레이블을 둔다. 기본 제목색에서 hover·focus 시 청록색으로 바꾸고 키보드 focus 외곽선은 자르지 않는다. 링크의 전환과 움직임 줄이기는 [공통 컴포넌트](components.md#textlink와-비조작-요소)를 따른다.

링크마다 최소 높이 44px를 확보한다. 세 행을 왼쪽으로 정렬하고 320px 기본 크기에서도 세 줄을 유지한다. 200% 텍스트 확대에서도 글자를 줄이거나 가로로 넘기지 않는다. Tab 순서는 GitHub → 전체 열람 → PDF 보기다. 행 순서는 데스크톱·모바일에서 같다.

## 전체 열람과 PDF

내용·페이지 나눔·브라우저 메뉴 인쇄는 [전체 열람·PDF 명세](pages/print.md)를 따른다. 정적 PDF는 전체 본문과 클릭 가능한 링크를 담고, 웹 문서는 같은 내용을 화면 폭에 맞춰 보여 준다.

## 제공·갱신 계약

고정 공개 주소는 `https://portfolio.seungju.dev/portfolio.pdf`다. 기존 Next.js 정적 산출물과 Cloudflare 자산 제공 경로를 사용한다. 응답은 200과 `Content-Type: application/pdf`이며 보기 주소에 강제 저장용 `Content-Disposition: attachment`를 설정하지 않는다. 저장 동작과 파일명은 브라우저·PDF 뷰어에 맡긴다.

고정 주소에는 `Cache-Control: public, max-age=0, must-revalidate`를 적용해 갱신 확인 없이 오래된 파일을 계속 재사용하지 않게 한다. 다음 요청의 재검증과 실제 새 파일 반영은 자산 제공 계층에서 확인한다. 다운로드용 별도 파일 복제나 별도 뷰어·서버 API를 만들지 않는다.

콘텐츠·인쇄 스타일을 변경하면 `pnpm pdf:generate`로 PDF를 재생성하고 전체 본문·링크·현재 8장 구성을 검증한다. 일반 빌드는 소스와 PDF의 대응 해시를 검사해 오래되거나 누락된 파일을 차단한다. 실행 환경과 갱신·캐시 검증 명령은 [PDF 운영 문서](../pdf-serving.md)를 따른다.

## 검토 기준

홈 1440·390·320px와 200% 텍스트 확대에서 세 링크가 잘리지 않고 같은 순서로 보여야 한다. 키보드·터치로 전체 열람은 같은 탭, PDF 보기는 새 탭으로 열리는지 확인한다. 제공 파일의 응답 상태·MIME·캐시 재검증·해시가 현재 PDF와 일치해야 한다. 로컬 검증과 공개 배포 확인은 구별한다.
