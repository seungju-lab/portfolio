# 정적 PDF 보기·다운로드

[Deliverable #54](https://github.com/seungju-lab/portfolio/issues/54)의 요구사항이다. 방문자는 홈에서 웹 전체 열람으로 이동하거나, 이미 생성·검증된 같은 PDF를 열고 저장한다. 브라우저 인쇄 설정을 조정해야 했던 다운로드 흐름을 정적 파일 제공으로 바꾼다.

## 홈 링크와 동작

기존 홈 목차 아래에 다음 세 줄을 배치한다. 둘째 줄은 두 개의 독립적인 링크이며 가운데 점은 장식 구분자다.

```text
GitHub
전체 열람 · PDF 다운로드
PDF 보기
```

| 링크         | 목적지                      | 실행 결과                                                               |
| ------------ | --------------------------- | ----------------------------------------------------------------------- |
| GitHub       | `https://github.com/ju1115` | 기존처럼 새 탭으로 이동한다.                                            |
| 전체 열람    | `/print/`                   | 같은 탭에서 웹 전체 문서를 읽는다.                                      |
| PDF 다운로드 | `/portfolio.pdf`            | `이승주-포트폴리오.pdf`라는 파일명으로 저장한다. 인쇄 창을 열지 않는다. |
| PDF 보기     | `/portfolio.pdf`            | 새 탭에서 PDF를 연다. 브라우저의 PDF 처리 설정을 따른다.                |

보기와 다운로드는 같은 PDF 파일을 사용한다. 보기 링크의 접근 가능한 이름에는 `새 탭`을 포함한다. 다운로드는 실제 링크와 download 속성을 사용하고 JavaScript 실행이나 중간 화면을 요구하지 않는다. 브라우저가 제공하는 저장·열기 UI를 사용하며 자체 진행률·성공 알림을 만들지 않는다.

## 배치와 상태

기존 TextLink의 색·서체·아이콘·hover·focus를 재사용한다. GitHub 로고, 전체 열람의 문서 아이콘, 다운로드의 아래쪽 화살표, PDF 보기의 새 탭 화살표로 동작을 구분한다. 아이콘은 보조 표시이며 각 링크에 전체 레이블을 둔다. 기본 제목색에서 hover·focus 시 청록색으로 바꾸고 키보드 focus 외곽선은 자르지 않는다. 다운로드 아이콘은 정지 상태를 유지한다. 다른 링크의 전환과 움직임 줄이기는 [공통 컴포넌트](components.md#textlink와-비조작-요소)를 따른다.

링크마다 최소 높이 44px를 확보한다. 세 행은 왼쪽으로 정렬하고 둘째 행의 두 링크와 구분자는 가운데 정렬한다. 둘째 행의 링크 사이 간격은 기존 16px 간격을 시작값으로 사용하고, 320px 기본 크기에서도 세 줄을 유지한다. 200% 텍스트 확대나 더 좁은 사용 가능 폭에서는 둘째 행의 줄바꿈을 허용해 글자를 줄이거나 가로로 넘기지 않는다. Tab 순서는 GitHub → 전체 열람 → PDF 다운로드 → PDF 보기다. 기본 크기의 행 순서는 데스크톱·모바일에서 같다.

## 전체 열람과 PDF

전체 열람 상단에는 `홈으로` 링크만 둔다. 기존 `PDF로 저장` 버튼, 그 버튼 전용 안내·오류·비활성 상태와 빈 영역을 제거한다. 별도 인쇄 버튼을 추가하지 않는다. 브라우저 메뉴·단축키 인쇄와 [8장 인쇄 레이아웃](pages/print.md#a4-배치)은 유지한다. 메뉴 인쇄 후 읽던 위치와 기존 포커스를 유지하며 사라진 버튼으로 포커스를 옮기지 않는다.

제공 PDF는 현재 전체 본문·본문 14px·행간 1.7, 남색·청록색, 사진·도식·내부 목차·외부 링크를 보존한다. 현재 콘텐츠에서는 8장이며 내용을 바꾸면 읽기 좋은 페이지 나눔을 다시 검증한다. 문서를 이미지로 만들지 않고 선택·검색 가능한 텍스트를 유지한다. 생성 시 배경 그래픽을 포함하고 브라우저 자동 머리글·URL·날짜는 제외한다. 기존 하단 이름·페이지 번호는 남긴다.

## 제공·갱신 계약

고정 공개 주소는 `https://portfolio.seungju.dev/portfolio.pdf`다. 기존 Next.js 정적 산출물과 Cloudflare 자산 제공 경로를 사용한다. 응답은 200과 `Content-Type: application/pdf`이며 보기 주소에 강제 저장용 `Content-Disposition: attachment`를 설정하지 않는다. 저장 여부와 파일명은 다운로드 링크에서 지정한다.

고정 주소에는 `Cache-Control: public, max-age=0, must-revalidate`를 적용해 갱신 확인 없이 오래된 파일을 계속 재사용하지 않게 한다. 다음 요청의 재검증과 실제 새 파일 반영은 자산 제공 계층에서 확인한다. 다운로드용 별도 파일 복제나 별도 뷰어·서버 API를 만들지 않는다.

현재 콘텐츠·인쇄 스타일에서 PDF를 재생성하고 전체 본문·링크·출력을 검사한 뒤 제공 파일을 교체하는 명령을 마련한다. 콘텐츠·인쇄 코드와 제공 파일의 대응 정보를 남겨 일반 빌드에서 오래된 PDF나 누락된 PDF를 감지한다. 의도적으로 입력을 바꾼 검사가 이를 실패로 검출하고, 재생성 후 정상 빌드가 통과해야 한다. 생성 도구 의존성과 실행 명령은 저장소에 기록하며 특정 세션의 `/tmp` 도구나 수동 복사만으로 갱신하지 않는다. 구현 상세와 명령은 Work #59에서 실제 동작을 확인해 기록한다.

## 작업과 검토 범위

Work #55에서 이 문서와 홈·전체 열람·공통 컴포넌트 명세를 맞춘다. #57에서는 홈 1440·390·320px, 전체 열람 1440·390px와 변경 링크의 상태를 Pencil에 반영한다. #59에서 정적 PDF 제공·갱신과 웹 링크를 구현하고 #62에서 실제 동작과 문서·시안의 일치를 검증한다.

기존 `projects/portfolio` 폴더만 사용한다. `main`의 `67c9d47`을 기준으로 `deliverable/54-pdf-serving`에 결과를 모으고 `work/55-pdf-serving-design`, `work/57-pdf-serving-pencil`, `work/59-pdf-serving-code`, `work/62-pdf-serving-validation`을 순차 통합한다. 기본 브랜치 병합과 공개 배포는 이 Work 실행의 전달 범위에 포함하지 않는다.

기존 A4 12장·압축안 8장 비교 시안과 프로젝트 상세는 보존한다. 모든 변경 화면의 렌더·저장, 320px·200% 확대·키보드·터치, 실제 새 탭·다운로드·저장 파일명과 보기/다운로드 파일 해시를 확인한다. PDF의 전체 페이지·텍스트·내부 목차·외부 링크·선택·검색, HTTP MIME·캐시와 재생성 검사를 수행한다. 로컬 자산 제공 검증과 공개 배포 확인은 구분해 기록한다.
