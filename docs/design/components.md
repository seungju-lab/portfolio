# 공통 컴포넌트

모든 원본과 스타일 변수는 `portfolio.lib.pen`에 정의하고 `portfolio.pen`에서 가져온 인스턴스를 사용한다. 화면별 텍스트·링크와 도식의 구성 요소·연결을 재정의한다. 같은 역할의 반복 요소는 원본과 변수 연결을 유지한다.

| 요소           | 구성과 동작                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| Profile        | 이름, 영문 직무, 두 줄 소개. 홈의 화면 크기별 변형에서 재사용한다. 상세 왼쪽은 프로젝트명과 역할을 사용한다.       |
| SectionLink    | 선과 목차 레이블. 기본·선택 상태는 선 길이와 대비로 구별한다.                                                      |
| TextLink       | 짧은 레이블과 이동 아이콘. GitHub·상세 이동·전체 열람·뒤로 이동에 쓴다. 아이콘과 목적지는 재정의한다.              |
| SkillTag       | 기술명과 작은 청록색 배경. 짧은 기술만 2~4개 사용한다.                                                             |
| ProjectEntry   | 날짜 열과 제목·역할·설명·기술·상세 링크. 모바일은 날짜를 위에 놓는다. hover/focus 상태를 별도 검토한다.            |
| EducationEntry | 기간, 과정명, 참여 상태와 관련 프로젝트. 근무 경력으로 표현하지 않는다.                                            |
| ArticleSection | 소제목과 본문. 기본 소제목·본문 표현을 재사용한다. 상세·전체 열람·PDF의 제목 계층과 배치는 페이지별 규칙을 따른다. |

반복 원본은 실제 콘텐츠가 들어간 상태로 검토한다. 링크 전체를 44px 이상의 조작 영역으로 제공하고, 기술 태그는 조작 가능한 버튼처럼 다루지 않는다. 인스턴스 내부의 긴 문장은 고정 높이로 자르지 않는다.

## 상세 전용 요소

아래 원본을 2026-09-14 Pencil 라이브러리에 반영하고 여섯 상세 시안에서 검토했다. 기존 색상·서체·간격 변수를 재사용하며, ArticleSection을 전역 변경하지 않았다. 페이지별 콘텐츠와 도식 구성은 [상세 문서](pages/project-detail.md)가 기준이다.

| 원본           | 라이브러리 ID | 화면 참조  |
| -------------- | ------------- | ---------- |
| DetailSection  | `A3IEM7`      | `u:A3IEM7` |
| SystemDiagram  | `ypTAB`       | `u:ypTAB`  |
| DiagramNode    | `mejVU`       | `u:mejVU`  |
| ChallengeBlock | `xIrsq`       | `u:xIrsq`  |
| ResultItem     | `f9UTO`       | `u:f9UTO`  |

### DetailSection

큰 제목과 해당 섹션의 내용 슬롯을 묶는다. 첫 섹션에는 상단 구분선을 생략하고 나머지는 기존 구분선 색의 선을 사용한다. 큰 제목은 데스크톱 24px·모바일 22px, 사례 제목은 기존 18px로 구별한다. 간격은 상세 페이지 규칙을 따른다. 정적 읽기 요소이며 hover·누름 상태를 만들지 않는다.

### SystemDiagram

도식 제목·담당 범례·노드·연결·설명으로 구성한다. 반복 노드는 투명 배경, 기존 구분선 색 1px 테두리, 6px 모서리와 역할 레이블을 사용한다. 담당 노드는 청록색 선과 텍스트 레이블을 함께 사용한다. 제목 14px·보조/연결 레이블 13px, 내부 여백 16px로 시작한다. 연결선은 독립 도형이며 사용자 조작 대상이 아니다. 그림의 노드 배치와 연결은 각 프로젝트 명세에 따르고 임의의 시스템 관계를 추가하지 않는다.

모바일에서 그림 전체를 축소하지 않고 연결을 세로 경로로 재배치한다. 글자 높이는 내용에 맞추고 상자의 고정 높이로 자르지 않는다. 확대·드래그·hover·클릭 반응은 없다. 웹 구현은 시각 도식을 접근성 트리에서 숨기고, 같은 관계·담당 범위를 설명하는 텍스트 목록을 figure 안에 제공한다. 도식 내부 폭이 26rem 미만이면 데스크톱에서도 세로 경로를 사용한다. 실제 구현·검증은 [웹 기록](../verification/project-detail-web.md)을 따른다.

도식 전체 제목은 18px이며, 반복 상자는 DiagramNode 원본의 14px 제목과 13px 역할 레이블을 사용한다. Matching SSAFY 데스크톱에서는 두 요청 경로를 각각 가로로 배치하고 상자 안의 `Spring Boot`와 `백엔드`를 두 줄로 나눈다. 모바일에서는 경로마다 React·연결 설명·Spring Boot를 위아래로 배치한다.

### ChallengeBlock

사례 제목과 레이블·본문의 반복으로 구성한다. 확인된 장애는 `문제 / 원인 / 해결`, 구현 과제는 `구현 과제 / 구현`을 사용한다. 원인을 확인하지 못한 장애 사례는 원인 칸을 생략한다. 빈 슬롯을 유지하지 않는다. 사례 제목 18px, 레이블 13px, 본문 16px와 기존 제목·본문색을 쓴다. 상태·포인터 효과를 추가하지 않는다.

### ResultItem

짧은 결과 제목과 설명을 묶는다. 투명 배경, 기존 구분선 색의 1px 테두리, 6px 모서리, 내부 여백 16px를 사용한다. 제목 18px·본문 16px이며 두 결과의 데스크톱 2열·모바일 1열 배치는 상세 문서가 기준이다. 이번 콘텐츠에는 확인된 성과 수치가 없어 제목을 강조한다. 검증 한계·회고는 결과 아래 일반 본문으로 제공한다. 링크·버튼 상태를 추가하지 않는다.

### Pencil에서 확정한 표현

데스크톱 결과 두 개는 더 긴 내용에 맞춰 같은 높이로 배치했다. ILOG 모바일의 긴 사례 제목은 의미 단위에서, Lorekeeper 모바일의 기여 요약은 `/` 뒤에서, 마지막 담당 항목은 `원고 관리,` 뒤에서 줄을 나눠 한 글자 고립을 없앴다. 글자 크기와 본문 의미는 유지했다.

화면의 목적지·새 탭 여부와 최신 설계 식별값은 Pencil이 유지하는 `context`에 기록한다. 현재 MCP의 편집 결과에서 링크 `href`와 갱신한 `metadata`는 보존되지 않았다. 기존 `metadata.sourceRevision`은 생성 당시 값이며, 정적 목적지 주석을 실제 웹 동작으로 간주하지 않는다. 저장 확인과 프레임별 렌더는 [상세 시안 검증 기록](../verification/project-detail-pencil.md)에 있다.

## 상태와 전환

시간·전환 곡선·입력 조건·중단·움직임 줄이기는 [공통 반응 규칙](foundations.md#반응과-움직임)을 따른다. 아래 상태는 웹 구현 명세다. Pencil의 정적 원본·인스턴스에 이 동작이 구현되어 있다는 뜻은 아니다.

### ProjectEntry

홈의 각 프로젝트 행을 하나의 내부 링크로 제공한다. 제목과 `상세 읽기`는 같은 목적지를 알리는 표현이며 Tab 정지점은 행당 하나다. 링크의 접근 가능한 이름은 프로젝트명과 상세 이동 목적을 포함한다. 기술 태그·설명 안에 별도 링크를 중첩하지 않는다.

| 상태·조건            | 표현과 결과                                                                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본                 | 배경 투명, 제목 `#E2E8F0`, 행 opacity 1, 화살표 이동 0.                                                                                                  |
| 포인터 진입          | 해당 행 배경 `#162238`, 제목 `#5EEAD4`, opacity 1. 나머지 프로젝트 행은 .9. 내부 이동 화살표는 오른쪽 4px로 이동한다.                                    |
| 포인터 이탈          | 다음 행에 진입하면 강조 대상을 바로 교체한다. 행 사이 빈 공간이나 목록 밖으로 나가면 모든 행을 기본 상태로 돌린다.                                       |
| 키보드 focus-visible | 해당 행에 공통 외곽선·강조 배경·청록색 제목·화살표 이동을 적용한다. 다른 행은 모두 opacity 1이다. focus 해제 시 현재 포인터 조건에 맞는 상태로 돌아간다. |
| 누름·실행            | 마우스 클릭·Enter·터치 한 번으로 해당 상세 경로에 진입한다. 별도 축소 효과나 지연은 없다. 터치의 첫 탭을 hover 미리보기에 소비하지 않는다.               |

전환 속성은 배경의 `background-color`, 제목의 `color`, 행의 `opacity`, 아이콘의 `transform`이다. 강조 배경 모서리는 6px이며 콘텐츠 바깥 좌우 24px·상하 16px에 배치한다. 배경은 장식 레이어로 두고 행의 padding·높이·클릭 범위를 상태마다 바꾸지 않는다. 모바일에서는 바깥 강조 배경을 숨기고 focus 외곽선과 제목으로 조작 대상을 표시한다.

목록 안에 focus-visible인 행이 있으면 그 행의 강조를 우선하고 다른 행의 hover 배경·제목 강조는 해제한다. 클릭해 focus-visible이 해제되거나 키보드 포커스가 목록 밖으로 나가면 현재 hover 상태를 다시 적용한다.

### SectionLink

데스크톱 기본 선은 폭 32px·높이 1px·`#475569`, 레이블은 `#8897AF`다. 선택된 항목은 선 64px와 선·레이블 `#E2E8F0`로 표시하고 `aria-current="location"`을 부여한다. hover와 focus에서도 같은 시각 강조를 사용하지만 현재 읽는 섹션은 바꾸지 않는다. focus에는 공통 외곽선을 추가한다. 전환 속성은 선의 `width`·`background-color`, 레이블의 `color`다. 이탈하면 실제 선택 상태로 복원한다.

모바일 가로 목차는 폭이 바뀌는 선을 없애고 레이블 아래 높이 1px의 밑줄과 밝기로 선택을 표시한다. 밑줄은 레이블 폭으로 고정해 다른 항목이 밀리지 않게 한다. 클릭·Enter·터치의 이동과 활성 판정은 [홈 탐색](pages/home.md#목차와-스크롤)이 기준이다.

### TextLink와 비조작 요소

텍스트 링크는 hover·focus에서 청록색으로 바뀐다. 오른쪽 이동 아이콘은 `(4,0)`px, 뒤로 이동은 `(-4,0)`px, 외부 링크의 대각선 아이콘은 `(4,-4)`px로 이동하며 해제하면 `(0,0)`으로 돌아간다. `color`와 `transform`에 공통 전환을 사용한다. 아이콘의 이동 공간 8px를 확보하고 글자·주변 요소의 위치는 유지한다. GitHub 로고와 인쇄 아이콘은 이동시키지 않는다.

내부 이동은 같은 탭을 사용한다. GitHub·저장소·레퍼런스 링크는 새 탭으로 열고 접근 가능한 이름에 `새 탭`을 알린다. 아이콘만 있는 링크에도 목적지를 이름으로 제공한다. 링크는 기본 브라우저의 새 탭 열기·주소 복사 동작을 유지한다. Profile·SkillTag·EducationEntry·ArticleSection에는 hover 배경·포인터 커서·누름 효과를 추가하지 않는다.

### 반응 검토 기준

프로젝트에 진입·이탈하고 두 행을 빠르게 왕복했을 때 마지막 입력에 맞는 강조만 남아야 한다. 이어서 Tab·Shift+Tab으로 이동하면 다른 행이 모두 선명해지고 외곽선이 잘리지 않아야 한다. 선택하지 않은 목차에 hover했다가 떠나도 `aria-current`는 원래 섹션에 남아야 한다. 390/320px 터치에서는 한 번의 탭으로 이동하며, 움직임 줄이기에서는 색·선택 상태는 구별되지만 이동 애니메이션은 없어야 한다.
