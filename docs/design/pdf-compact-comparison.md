# PDF 압축안 비교

현재 12장과 내용·글자 크기를 유지한 압축안을 [portfolio.pen](../pen/portfolio.pen)에서 함께 비교한다. 2026-09-15 사용자의 코드 구현 요청으로 8장안을 채택했다. [전체 열람·PDF 명세](pages/print.md)에 현재 적용 규칙을, [구현 검증 기록](../verification/compact-pdf.md)에 실제 출력 결과를 기록한다.

## 유지할 내용과 바꿀 배치

소개, 사진, 세 프로젝트의 개요·아키텍처·문제 해결·결과, 교육·활동과 연락 경로를 모두 유지한다. 콘텐츠 출처는 [홈 데이터](../../src/content/portfolio.ts), [상세 데이터](../../src/content/project-details.ts)와 저장된 기존 A4 12장이다. 문단을 요약하거나 성과를 추가하지 않는다.

A4 794×1123px, 안쪽 여백 60px, 남색 배경·청록색 강조와 가져온 인쇄 테마를 유지한다. 본문은 14px·행간 1.7, 도식은 기존 12~14px를 유지한다. 배치를 맞추려고 글자를 더 작게 만들지 않는다. 제목·역할·링크와 각 섹션의 시각적 위계를 보존한다.

개요의 주요 기능과 담당 범위를 나란히 놓고, 프로젝트 제목 옆에 기간을 배치한다. 저장소와 상세 링크도 같은 행에 둔다. 아키텍처는 요청 방향과 담당 표시를 보존하면서 연결 레이블·화살표를 가로로 묶어 불필요한 세로 간격을 줄인다. 소개와 목차는 교육·활동과 한 장에 묶어 마지막 장의 큰 빈 공간을 없앤다.

검토한 압축안은 8장이다. 소개·목차·교육 1장, ILOG 3장, Lorekeeper 2장, Matching SSAFY 2장으로 구성한다. 각 프로젝트의 첫 장에는 개요와 아키텍처, 이후 장에는 문제 해결과 결과를 배치한다. 향후 브라우저 출력에서 같은 본문이 읽기 좋은 크기로 들어가지 않으면 9장으로 늘릴 수 있다. 8~9장은 업계 표준이 아니라 현재 콘텐츠에 대한 제안이다.

## 참고한 실제 PDF

- [박봉호 포트폴리오](https://dev-leo.site/park-bongho-portfolio.pdf): A4 세로 8장. 3~4장의 소개·담당 범위·기술·성과를 묶은 배치를 참고해 프로젝트 개요의 기능과 담당 범위를 병렬로 배치한다. 원문의 성과나 표현은 가져오지 않는다.
- [류병선 포트폴리오](https://ryubyeongsun.github.io/bs_00.github.io/portfolio.pdf): 가로 19장. 4장의 개요·아키텍처 병렬 구성, 6~7장의 문제·해결·결과를 함께 읽는 구성을 참고한다. 현재 A4에서는 전체 폭의 도식과 짧은 병렬 정보 묶음을 조합한다.
- [Saleh Sadid Mir 포트폴리오](https://raw.githubusercontent.com/salehsadid/CV-and-Portfolio/main/Saleh_Sadid_Mir_Portfolio.pdf): 가로 11장. 6~9장의 여러 프로젝트를 묶고 관련 링크를 남기는 방식은 목차의 밀도와 링크 유지에 참고한다. 프로젝트 설명을 짧은 카드로 대체하는 방식은 이번 전체 본문 보존 조건에 적용하지 않는다.

세 PDF의 실제 페이지와 대표 렌더를 확인했다. 장수 자체보다 관련 정보를 같은 면에서 읽게 하는 배치를 참고한다.

## 비교와 검토 기준

기존 A4 12장은 보존하고 같은 캔버스의 가까운 새 행에 압축안을 배치한다. 각 프로젝트의 시작 위치를 맞춰 위아래에서 분량과 밀도를 비교할 수 있게 하고, 캔버스 바깥 설명으로 현재안과 제안안을 구별한다. 인쇄 본문에는 작업 메모를 넣지 않는다.

대표 ILOG 개요·아키텍처를 먼저 렌더한 뒤 나머지 프로젝트와 소개 페이지에 확장한다. 모든 페이지에서 본문·도식의 잘림, 겹침, 지나치게 좁은 열, 잘못된 요청 방향을 확인한다. 기존 페이지와 압축안의 표시 텍스트를 대조하며 페이지 번호와 중복된 섹션 제목은 구별한다. 라이브러리 변수·컴포넌트 연결을 유지하고 원본 페이지가 변경되지 않았는지 확인한다.

목차와 외부 링크의 표현·목적지는 유지한다. 정적 시안에는 별도 전환 효과가 없다. 실제 브라우저 페이지 나눔, PDF의 텍스트 선택·링크 실행과 배경 그래픽 설정은 향후 코드 반영 시 검증한다. Pencil 시안의 장수를 실제 출력 결과로 간주하지 않는다.

## 시안 상태

2026-09-14에 Pencil MCP로 8장 전체를 구성하고 렌더를 검토했다. 기존 12장은 y=0에 보존했고, 압축안은 y=2401에 배치했다. 프로젝트별 시작 x 좌표를 맞춰 위아래에서 비교한다. 기존안 위에는 `현재 PDF · 12장`, 압축안 위에는 `압축안 · 8장 / 본문과 글자 크기 유지` 안내가 있다.

| 압축안 | 구성                          | 프레임 ID | x 좌표 |
| ------ | ----------------------------- | --------- | ------ |
| 01     | 소개·목차·교육·연락           | `IoThK`   | 5500   |
| 02     | ILOG 개요·아키텍처            | `wjwOT`   | 6454   |
| 03     | ILOG 문제 해결 1·2            | `D0qn3k`  | 7408   |
| 04     | ILOG 문제 해결 3·결과         | `adW1H`   | 8362   |
| 05     | Lorekeeper 개요·아키텍처      | `L59APt`  | 11224  |
| 06     | Lorekeeper 문제 해결·결과     | `p4ycT`   | 12178  |
| 07     | Matching SSAFY 개요·아키텍처  | `TfERu`   | 14086  |
| 08     | Matching SSAFY 문제 해결·결과 | `sYnOX`   | 15040  |

각 프레임의 metadata에는 이 문서와 `paper/compact/01`부터 `paper/compact/08`까지의 viewKey, 비교 제안 상태를 기록했다. 교육·활동의 기존 마지막 장 아래에는 첫 장으로 통합했다는 비교 메모를 배치했다.

기존안과 압축안의 표시 텍스트 223개를 개수까지 대조했고 차이가 없었다. 텍스트별 글꼴·크기·행간·색도 같은 값으로 확인했다. 바닥글의 페이지 번호는 8장에 맞게 바꿨고, 이어지는 페이지에는 프로젝트 이름을 추가했다. 링크 목적지 주석도 기존안과 일치한다. 도식의 요청·양방향 연결을 유지하면서 화살표를 기존 보조 색으로 표시했다.

8장 모두 전체 렌더를 확인했고 표시 요소의 잘림 경고와 미완성 placeholder가 없다. 본문 높이는 순서대로 846·955·649·684·959·923·956·834px이며 바닥글까지 최소 26px가 남는다. ILOG의 사례 페이지에는 다른 장보다 여백이 더 남지만, 세 사례와 결과를 한 장에 억지로 넣지 않고 사례 단위를 유지했다. 공유 라이브러리를 수정하지 않고 기존 변수·컴포넌트 참조를 사용했다.

2026-09-15에 사용자 저장 응답과 `portfolio.pen`의 파일 수정 시각·Git 변경 통계로 저장을 확인했다. MCP에서 압축안 8개 프레임의 ID·A4 크기·viewKey와 미완성 표시가 없음을 재확인했다. 비교 시안과 문서 작성은 완료했다. 비교 시안 작성 당시에는 웹 코드와 브라우저 PDF 출력을 변경하지 않았다. 이후 사용자의 구현 요청에 따라 같은 문서 순서와 인쇄 레이아웃을 코드에 반영했다. 비교를 위해 Pencil의 기존 12장과 압축안 8장을 모두 유지한다.
