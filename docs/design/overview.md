# 이승주 포트폴리오

Java 백엔드 개발자를 검토하는 채용 담당자와 기술 면접관이 담당 범위와 문제 해결 경험을 읽는 웹 포트폴리오다. 홈에서 세 프로젝트를 비교하고, 상세에서 구현 과정과 검증 범위를 확인하며, 인쇄용 페이지에서 같은 사실을 문서로 읽는다.

## 시각 방향

사용자가 선택한 [Brittany Chiang](https://brittanychiang.com/)을 단일 레퍼런스로 사용한다. 2026-09-09 실제 브라우저의 1440×1000, 390×1000 화면을 확인했다. 데스크톱의 왼쪽 이름·직무·목차와 오른쪽 본문, 짙은 남색 바탕, 절제된 청록색 강조, 테두리 없는 이력 목록을 적용한다. 원본의 문장·경력·사진은 사용하지 않는다.

왼쪽은 정체성과 탐색, 오른쪽은 읽는 내용이라는 역할을 유지한다. 이름은 크게, 프로젝트 제목은 본문보다 약간 크게 둔다. 모든 섹션을 큰 제목·카드·도해로 재구성하지 않는다. 한국어 본문은 Noto Sans KR로 바꾸고, 짧은 소개 다음에 대표 프로젝트가 나타나도록 원본보다 소개 분량을 줄인다. 첫 화면에서 장식보다 이승주라는 이름과 백엔드 역할을 먼저 알아볼 수 있어야 한다.

## 콘텐츠와 순서

1. ILOG: 인증·사용자·그룹·Gateway를 단독 구현한 범위와 로그인 이후 요청 흐름을 고친 경험이 구체적이어서 대표작으로 둔다.
2. Lorekeeper: 현재 진행 중인 로그인 프론트엔드·백엔드와 Work·Episode 개발을 보여 준다. AI 탐지 엔진을 본인 기여로 쓰지 않는다.
3. Matching SSAFY: 팀 도메인과 WebSocket·STOMP 채팅 구현을 보여 준다.

홈의 짧은 작업 방식 문단에 홈서버 활용과 이슈 관리 설계를 담는다. 확인되지 않은 사용자 수·성과 수치·수상·프로필 사진·이메일·이력서 파일을 추가하지 않는다.

## 반응 조사와 적용 결정

2026-09-09 [Brittany Chiang의 공개 사이트](https://brittanychiang.com/)를 Chromium에서 조사했다. 1440×1000 화면에서 포인터 이동·행 진입과 이탈·목차 클릭·Tab·문서 스크롤을 실행했고, 390×1000 터치 에뮬레이션에서 단일 열과 고정 소제목을 확인했다. `prefers-reduced-motion: reduce` 적용과 새로고침 후의 스타일도 확인했다. 입력은 브라우저 자동화로 전달했으며 실제 휴대폰 검증은 하지 않았다. 데스크톱 에뮬레이션의 hover 미디어 질의는 false였지만 전달한 마우스 이벤트로 실제 hover 상태가 발생했다.

| 반응 | 관찰 또는 계산된 스타일 | 포트폴리오 적용 결정 |
| --- | --- | --- |
| 커서 조명 | 포인터를 따라 중심이 바뀌는 반경 600px의 파란 방사형 배경. 색은 `rgba(29,78,216,.15)`, 투명 지점은 80%. | 홈·상세에 채택한다. 좌표계와 진입·이탈 규칙은 [홈 명세](pages/home.md#커서-조명)로 정하고 터치·움직임 줄이기에서는 끈다. |
| 프로젝트 강조 | 제목 청록색, 배경 강조, 다른 행 opacity .5. 이탈하면 복원된다. 화살표 transform은 `(0,1)`에서 `(4,-4)`px로 변한다. | 기존 행 배경색을 유지한다. 다른 행은 읽기 대비를 위해 .9로 조정하고, 내부 이동 화살표는 수평으로 움직인다. |
| 전환 | 행·목차 선 150ms, `cubic-bezier(.4,0,.2,1)`. 화살표는 transform 전환. | 공통 전환값으로 채택한다. 변경 속성은 요소별로 제한한다. |
| 목차·스크롤 | 선 32→64px. 클릭 시 hash와 스크롤이 바뀌며 도착 지점 상단 여백은 데스크톱 96px. 수동 스크롤은 선택 목차를 바꾸지만 hash를 바꾸지 않는다. | 채택한다. 활성 판정선·포커스·중단 규칙은 자체 설계로 보완한다. 원본의 정확한 활성 판정 알고리즘은 확인하지 않았다. |
| 좁은 화면 | 소개도 문서와 함께 스크롤되고 소제목은 화면 위에 붙는다. 프로젝트 hover 배경과 다른 행 흐림은 나타나지 않는다. | 소제목 고정을 채택한다. 기존 포트폴리오의 모바일 가로 목차는 유지한다. |
| 키보드·움직임 줄이기 | Tab으로 프로젝트 링크에 진입하면 화살표가 이동하나 다른 행은 흐려지지 않았다. 움직임 줄이기에서는 선·화살표의 transition-property가 none이지만 smooth scroll과 커서 조명은 남았다. | 키보드 외곽선을 명시한다. 움직임 줄이기에서는 조명·화살표 이동·부드러운 스크롤까지 끈다. |

조명의 CSS에 선언된 300ms는 배경 좌표가 실제로 300ms 동안 보간된다는 근거가 아니다. 앵커 이동도 브라우저의 smooth scroll이므로 고정된 소요 시간으로 기록하지 않는다. 프로젝트 이미지의 테두리 반응은 사용할 이미지가 없어 제외한다. 개인 취미 장식과 별도 아카이브 기능은 이 포트폴리오의 읽기·탐색 과제에 포함하지 않는다.

표의 관찰값을 제외한 적용 수치와 입력 대안은 이 포트폴리오를 위한 설계값이다. [공통 전환](foundations.md#반응과-움직임), [요소 상태](components.md#상태와-전환), 각 페이지의 탐색·검토 기준이 구현 기준이며 레퍼런스의 모든 동작을 복제한다는 뜻은 아니다.

## 반응 명세 검토 상태

조명, 행 강조, 링크·목차, 스크롤 탐색, 상세 이동, 인쇄에 대해 시작·해제·반복·입력 대안과 수용 기준을 문서에 반영했다. 레퍼런스 브라우저 조사와 문서 간 상태 전이 검토를 완료했다. 대상 사이트의 동작 구현, Pencil 상태 시안 갱신, 실제 기기와 브라우저 인쇄 검증은 아직 수행하지 않았다. 각 페이지의 반응 검토 기준은 이후 구현에서 통과해야 할 항목이다.
