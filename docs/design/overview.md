# 이승주 포트폴리오

Java 백엔드 개발자를 검토하는 채용 담당자와 기술 면접관이 담당 범위와 문제 해결 경험을 읽는 웹 포트폴리오다. 홈에서 세 프로젝트를 비교하고, 상세에서 구현 과정과 검증 범위를 확인하며, 전체 열람과 PDF에서 같은 내용을 읽는다.

## 시각 방향

짙은 남색 바탕과 청록색 강조, 테두리 없는 이력 목록을 사용한다. 데스크톱은 왼쪽에 이름·직무·목차, 오른쪽에 본문을 두고 모바일은 한 열로 읽는다. 한국어 본문은 Noto Sans KR, 영문 직무·기술명·날짜는 Inter를 사용한다. 이름과 백엔드 역할을 먼저 알아볼 수 있게 하고, 짧은 소개 다음에 대표 프로젝트를 배치한다.

상세는 프로젝트 개요·아키텍처·문제 해결·결과의 네 섹션으로 구분한다. 전체 열람과 8장 PDF는 상세의 전체 본문·사진·도식을 공유한다. 색·글꼴·간격·반응은 [공통 규칙](foundations.md)을 따른다.

## 브라우저 탭

홈 제목은 `이승주`다. 프로젝트 상세는 `이승주 | ILOG`, `이승주 | Lorekeeper`, `이승주 | Matching SSAFY`, 전체 열람은 `이승주 | 전체 열람`으로 이름을 앞에 통일한다.

공통 파비콘은 남색 `#0F172A` 바탕에 청록색 `#5EEAD4`의 굵은 `SJ`를 둔 둥근 사각형 SVG다. 글자는 경로로 표현해 설치된 글꼴에 영향을 받지 않게 한다. 16px·32px에서 두 글자를 구별할 수 있어야 한다.

## 콘텐츠 기준

프로젝트 순서는 ILOG, Lorekeeper, Matching SSAFY다. ILOG는 인증·사용자·그룹·Gateway 담당 범위와 로그인 요청 흐름 개선을, Lorekeeper는 로그인·작품·회차 개발을, Matching SSAFY는 팀 관리·실시간 채팅 구현을 보여 준다. Lorekeeper의 AI 탐지 엔진을 본인 기여로 쓰지 않는다.

홈의 작업 방식 문단에는 홈서버 활용과 이슈 관리 설계를 담는다. 확인된 프로필 사진과 프로젝트 기록을 사용하고, 근거 없는 성과 수치·수상·이메일·이력서 파일은 추가하지 않는다. 구현, 당시 확인한 동작, 테스트 작성과 현재 재실행 결과를 구별한다.

- [홈 콘텐츠](../../src/content/portfolio.ts): 소개·프로젝트 요약·교육·활동·연락 경로.
- [상세 콘텐츠](../../src/content/project-details.ts): 개인 기여·시스템 구성·사례·결과·검증 한계.
- [상세의 콘텐츠 근거](pages/project-detail.md#콘텐츠-근거): 프로젝트별 지식 기록과 적용 범위.

## 설계 근거

[Brittany Chiang](https://brittanychiang.com/)의 두 열 배치·남색과 청록색·목차·커서 조명·행 강조를 참고했다. 원문의 경력·문구·사진은 사용하지 않는다. 2026-09-09 브라우저에서 데스크톱과 모바일, 포인터·키보드·스크롤 반응을 확인했다. 다른 프로젝트 행의 불투명도는 읽기 대비를 위해 .9로, 내부 이동 화살표는 수평 이동으로 정했다. 움직임 줄이기에서는 조명·전환·아이콘 이동·부드러운 스크롤을 끈다.

[Dinesh Gaikwad의 Developer Portfolio 상세](https://dineshgaikwad.vercel.app/projects/portfolio)의 개요·아키텍처·문제 해결·결과라는 정보 구성을 채택했다. 원문의 본문 구조를 확인한 것이며 카드 외형·치수·움직임을 복제한 명세가 아니다. 섹션 간격·도식 재배치·결과 테두리는 이 포트폴리오의 자체 설계다.

PDF의 관련 정보 묶음과 분량에 대한 근거는 [인쇄 배치 근거](pages/print.md#인쇄-배치-근거)에 둔다.
